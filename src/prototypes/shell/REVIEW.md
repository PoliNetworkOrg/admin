# Rail dashboard — design review

Reviewed: commit `c729915` ("resolve Rail review findings") served at `http://localhost:18482/dashboard` with `AGENT_MODE=true` and the mock backend on port 3000. Spec: `docs/design.md` (the promoted copy of the prototype's `DESIGN.md`, including its amendments: branded service logos, `SectionEmpty`, row-action order `⋮ ✎ 🗑`, search up to 360px, Records palette group deferred). The `src/prototypes/shell/` directory was removed while this review ran (the shell now lives in `src/components/shell`, primitives in `src/components/primitives`, pages in `src/features/**`), so file references below point at the promoted code. Pre-redesign production is commit `f9d6480`.

Method: every route screenshotted at 1440×900 light and dark and at 1000×800 light, plus 600×800 for the sheet; 50 interaction captures over CDP (every dialog, inline edit, popover, confirm, toast, tooltip, keyboard focus order, focus return after dialogs, `/` and `⌘K`); full read of the shell, the primitives and every feature page and dialog; copy and behaviour diffed against `f9d6480` for Account, WhatsApp, FAQs, Telegram user detail, Telegram groups, labels, projects and guides. The four parallel review subagents were terminated by an org spend limit before producing output, so this is one reviewer's complete pass. Items on the polish agent's known list (IconButton aria label, actions width, chip overflow, selector chip overlap, avatar initials, focus-vs-error border, dialog outline, inline-edit error props, disabled style, segmented primitive, dropdown styling, `?q=` helper, license casing, publication names, users roles column, batch report actions, associations insert-at-top) are not repeated.

## Executive summary

1. The build is faithful to `docs/design.md` and to the owner's four constraints. Wayfinding is stated once per level everywhere: service in the panel header, section in the panel, record in one `h1`, parent context in the bar; no breadcrumb, eyebrow or dialog eyebrow survived, and the `<1024` "Service › Section" row only appears when the panel is gone.
2. Normalization is complete: every destructive action is a `ConfirmDialog` with "{Verb} {object}?" and a verb+object confirm label; every dirty form dialog asks "Discard changes?"; toasts follow §8.3 (no "successfully", no quotes); empty states follow §8.4; `—` replaces every "Not set"/"No …" string; no `transition-all`, uppercase, italic, raw hex or palette utility exists outside `LabelChip`/`LabelDot`.
3. Keyboard and focus work: rows are tab stops with "Open {name}", `/` focuses the search, confirm and form dialogs return focus to their trigger (verified after a nested Discard), rail roving tabindex and panel arrows work, optimistic report removal moves focus to the next row.
4. Dark mode has no defects: solid borders, no glow, raised layers ring instead of shadow, branded logos readable, label pills legible.
5. The Account page is the clearest page in the app: one card per concern, read-only values as key/value rows, one primary per region, destructive zone separated by 48px. Two small clarity tweaks are listed (F-40, F-41).
6. Most important fix: the header-bar toolbar wraps into three rows at 1000px (search alone, then filters and count), against the two-row rule in §2.3 (F-01).
7. Second: the Grants search placeholder is clipped at 280px ("Search users, authorizers or reas") (F-02).
8. Third: the Members count says "24 licenses" but counts only Office 365 licenses (F-03).
9. Fourth: empty tables keep a header row whose columns collapse to the right edge because the fill column keeps `max-width: 0` (F-04).
10. Fifth: the rail link and the panel item both carry `aria-current="page"`, so assistive tech hears the location twice, which is the one place constraint 1 leaks (F-05). Everything else is P2 polish; nothing from production was lost except two small copy nuances (see "Lost vs production").

## Verified behaviours (no finding)

- Focus returns to the opening button after `ConfirmDialog` (passkey delete, leave group) and after a nested "Discard changes?" on a form dialog.
- `/` focuses the page search from the body; `Tab` walks rows in order with "Open {name}"; `Esc` clears a filled search.
- Visibility toggle: one in flight, `EyeOff` in warning color, toast "{title} is now hidden.", revert on failure (code path).
- Optimistic report removal: 120ms fade, focus kept on the next row, panel count decrements after `invalidate`.
- Theme toggle swaps instantly; dark surfaces, borders and raised layers match §3.3/§3.4; no `border-white/10`.
- `canWrite` gates every mutation control on every page (`useCanWrite` / `useCanWrite("web")`), including empty-state actions and row actions.
- `document.title` is set once from the route; section pages render exactly one sr-only `h1`, deep pages one visible `h1`.
